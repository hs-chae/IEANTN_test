## Explicit trust boundaries

The mathematical source-to-AST correspondence, typed execution, loop/function
correctness and source-output-to-IEANTN consumer chain are checked by the Lean
kernel. The generic compiler/core-runtime, operating-system and hardware
contracts are the owner-approved external boundary; no application-specific
correct output, successful effects, intended memory representation or raw
completion is assumed as a platform fact. The C standard-library/ABI contract
for the separate verified fixed-input quotient driver is documented separately.

The typed model supports the documented GCC/Clang unsigned128 extension and the
specified integer widths. Native compiled source observations and differential
cross-checks have separate receipts and remain ordinary empirical observations;
those observations are not substituted for kernel source executions. Python
proposal generators and ordinary Lucas/composite certificates are independently
checked inputs, not themselves source-first PV. The adaptive C++ caller, its
full remaining finite workload, and physical process association for every
possible caller remain separate obligations.
