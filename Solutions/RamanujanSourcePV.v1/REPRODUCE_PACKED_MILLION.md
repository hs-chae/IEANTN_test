38,358,837,683 inclusive to 38,359,837,684 exclusive, with the same strict
Ramanujan gap greater than 501,901. The packed proof replaces the old local
primality-certificate providers. The original rows, values, interval and margin

bitset implementation has been source-verified. Native proposal generation is
untrusted until the kernel checks pass. Physical loading, native callers and
execution/output association retain the separately documented boundaries.

## One clean replay

Use the owner repository and exact commit specified by the supplement's final
publication receipt. Linux x86-64, Python 3.11, Git, Elan, a C++ compiler and the
baseline generator's recorded Python dependencies (Sympy 1.14.0 and mpmath
1.3.0 in the accepted run) are required. From the root
obtain the pinned generic libraries with `lake exe cache get`. Lean is
4.34.0-rc2; Mathlib is `71a80585ee495fc24472fd0eaffc89d94e4fd8d6`.
Create a fresh context with `scripts/bootstrap_context.py` as described in
`REPRODUCE_COUPLED_ANALYTIC.md`, then run from this solution directory:

```sh
python3 scripts/reproduce_packed_million.py \
  --context /data/ivy-ramanujan-source-pv-20261119/packed-clean-context.json \
  --out /data/ivy-ramanujan-source-pv-20261119/packed-clean-full \
  --bound-result --jobs 6 --cpus 84,85,86,87,88,89
python3 -OO scripts/reproduce_packed_million.py \
  --check /data/ivy-ramanujan-source-pv-20261119/packed-clean-full
```

Choose fresh filenames and available CPU cores. The default pipeline
regenerates the original critical-pair source data and the fixed local rows,
regenerates both new packed numerical proposals, verifies every required source
hash, stages only the selected source modules, and builds all 549 application
modules plus a fresh final theorem audit. Only pinned generic libraries are
reused. This does not run the unrelated full 1.49-trillion native experiment.

The resource policy uses at most 300 GiB per worker and in aggregate for this
proof run, with 192/96 GiB profiles where previously measured necessary. It
requires genuinely available 1 TiB RAM, a 512 GiB host reserve, independently
1 TiB free disk, and at most 300 GiB total owned scratch. The frontend checks
15 GiB forecast headroom before preparation and proof launch; the unchanged
proof backend checks its own 3 GiB forecast while scheduling workers.
The guarded proof backend pauses new dispatch when resources are low and
drains active workers on a signal or failure. Preparation finishes its current
child and records a checkpoint when interrupted. It never promotes a partial
checkpoint to mathematical acceptance.
