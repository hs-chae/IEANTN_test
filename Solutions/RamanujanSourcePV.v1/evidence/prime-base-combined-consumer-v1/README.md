# Combined certified-base and balanced-data provider

The alternative provider is actually consumed by the same original 285
source-count pairs and the same Ramanujan result: every real input from
38,358,837,683 inclusive to 38,359,837,684 exclusive has gap greater than
501,901. This is an alternative verified proof path, not a stronger
number-theoretic theorem. It preserves all original rows, assumptions, Q
computations, source-count anchors, scalar programs and six C source bindings.

The new P path closes the small-prime list's membership and completeness
certificate, directly executes its fold against standalone balanced
4096-bit data in the Lean kernel, and proves equality with the canonical P
mask. It does not import or consume the old full P-mask equality, old P-mask
data/calibration providers, or old local-primality/Lucas proof providers.
All 285 unchanged P-prefix checks were recomputed. The same generic source
provider constructs the actual C checker executions from proved input words;
the existing C counter/scalar proofs then supply the unchanged real theorem.

The prime-list fold and balanced codec are Lean-kernel numerical computations.
They are not source-first PV of a new native C codec or bitset program. The
source-first part remains the existing source-linked C count/checker/e/log/cell
programs. Physical input loading, native callers and process/output association
keep their separately documented boundaries. No overall performance or
best-known-result claim is made by this integration.

Accepted modules are `PrimeBaseCombinedQueries` (27.202 seconds),
`PrimeBaseCombinedMillion` (4.225 seconds), `PrimeBaseCombinedResult`
(4.131 seconds), and `PrimeBaseCombinedIndependentAudit` (86.648 seconds).
The complete certificate, real-interval and gap closures contain respectively
59,289, 59,321 and 59,328 constants. The audit checks the exact original real
statements, zero/three/three binders, the closed new list/data path, all source
count/e/log/cell/anchor paths, and exclusion of old proof providers. Only the
standard Lean axioms occur in all 14 printed theorem audits. Actual imported
modules are recorded separately; unchanged incidental raw-data imports remain.

This was an incremental host build against already accepted exact application
objects. It is not a new wholly fresh replay. The frozen old 548/549 sources,
their receipts and their running clean replay were not changed.

application bank, regenerate/compile the independently recorded combined
