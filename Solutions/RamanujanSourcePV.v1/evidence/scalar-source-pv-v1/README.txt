Reproduce from a clean environment

First follow the main project README/bootstrap to create CLEAN_CONTEXT with the
pinned Lean4.34.0-rc2 compiler and pinned generic dependency libraries. Its
application object directory must be fresh. Then use the full local-stage hook:

  bash scripts/reproduce_local_million_full.sh CLEAN_CONTEXT FRESH_LOCAL CPUS JOBS

This regenerates all958 original accepted source files and compiles the actual
local mathematical/count proof prerequisites with no inherited application
objects. Its source-only --prepare-only route is NOT a full proof replay.
The actual full cold replay was still running at this checkpoint; do not
misrepresent the checked generation receipt as completion of that replay.

Once that preceding clean local stage has completed, run from the solution:

  bash scripts/reproduce_finite_scalar_source.sh CLEAN_CONTEXT \
    FRESH_LOCAL/proposals/million-cells/source/RamanujanPV/LocalCellsMillion/Data.lean \
    FRESH_SCALAR_OUTPUT CPU [FINAL_CONSUMER_MODULE ...]

This deterministic wrapper regenerates all three actual C files and structured
ASTs, rebuilds the complete scalar proof core, regenerates and kernel-executes
all285 log inputs and all285 seven-field calls, compiles all three285-row collectors (log, source cell execution and non-strict
applicability), rebuilds Protected and the final FiniteProgramMillion theorem,
performs fresh independent exact-type/axiom/current-C-byte audits, and compiles
and runs the actual GCC C source on all285 original records. Output directories
must be fresh and belong to the configured experiment scratch tree. There are
no random seeds. Exact numerical parameters are fixed by source and preserved.
The generators and native observer accept --context and write only under that
context's owned scratch root. Actual relocation outside the old fixed /data
experiment prefix passed in normal/-O/-OO modes; all30 generated proof source
modules per mode are byte-identical to the original scientific proofs.
The core source-binding stages use96GiB address-space ceilings; numeric stages
use measured-sufficient24GiB. The launcher checks actual available RAM and keeps
512GiB for the host. A96GiB request is permitted only with genuinely1TiB available.
The wrapper has passed shell syntax checks and all its constituent scientific
and audit steps have executed, but the full wrapper cold-baseline run is not

Storage and remaining generic trust

All new scalar numerical proposals/receipts/source are small (the selected owned
resource summary including new proof objects totals about24.4MB, excluding shared pre-existing dependencies).
No large prime lists or numerical scratch arrays were generated by this overlay.
Keep original locked inputs, accepted proof objects, essential source and receipts.
There is no need to retain temporary copies of already-regenerable caches. Any
cleanup must first prove exact ownership and regeneration, preserve the accepted
canonical artifacts, and avoid the original count studies' directories.

The selected model is a restricted typed C subset, not a formalization of the
entire C standard or GCC. Pinned compiler lowering, linked __udivti3/__udivmodti4
runtime helpers, C preprocessing/include association, dynamic loader/ctypes ABI,
OS and hardware remain generic trusted contracts. The measured GCC LP64 target
has int32,long64,uint64 and unsigned128, matching the proved operations. Actual
application initialization, source expressions, loop execution, helper response
realization and output/mathematical association are proved separately. Do not
expand generic platform runtime internals or relabel ordinary native observations
and unrelated kernel-only certificates as source-first program verification.
