# Reproducing the four corrected-followup cube reviews

`historical/` retains byte-exact controllers used for the recorded posthoc review receipts. Those historical controllers contain machine-local paths and are evidence of the actual executed procedure, not portable launchers. The two parent-directory scripts are new path-parameterized counterparts; they retain the arithmetic and compilation procedures, but have different controller hashes. The historical receipts are never relabeled as runs of the newer portable controllers.

All numerical checks are ordinary external exact-rational Python evidence (**E**), not Lean kernel proofs or source-first PV. `replay_rational_checks.py` verifies every selected prefix file against its captured `LOCK.json`, then replaces Python assert statements with explicit exception guards while preserving the arithmetic AST and exact parameters. The original source is unchanged. This avoids inactive checks under Python optimization. Historical replay receipts and stdout show normal, -O and -OO executions; original unmodified sources were additionally executed with optimization disabled and produced the same output. No formal Python execution semantics is claimed.

Example from the repository root (replace OUT by a fresh absolute directory):

```sh
python3 Solutions/RH080Study.v1/ablation/followup/reproduction/replay_rational_checks.py --prefix-dir Solutions/RH080Study.v1/ablation/followup/timely-prefixes/cube-L2_E2_D1_V1-r1/prefix-0002 --trial cube-L2_E2_D1_V1-r1 --prefix prefix-0002 --script scalar_checks.py --script sinc_certificate.py --script finite_cover.py --mode normal --run OUT
```

Repeat with --mode O and --mode OO and distinct fresh output directories. The late sinc certificate deterministically checks 196608 whole integration cells; it is neither random nor a sample-only claim. The other trial commands use the same helper and their curated last-prefix directories: V0r0 `cube_sieve.py`; V0r1 `scalars.py` and `notches.py`; V1r0 `exact.py`. The scripts preserve all original mathematical constants and source claims. Their outputs support the independently reviewed written argument and are never promoted to verified network facts.

`recompile_submitted.py` is an **optional focused** posthoc Lean replay. It requires explicit paths to the exact pretrial baseline compile directory (source plus objects), its assigned E2 source tree, and the assigned V0 or V1 support compile directory (source plus objects), as well as the pinned generic Lean context. It checks all 300 baseline sources against the assigned source tree and overlapping support sources, compiles byte-exact locked submitted files, and audits selected actual theorem types, proof values and axioms. It intentionally does not promise a clean automatic bootstrap of those historical banks, and does not count as a fresh complete application closure or evidence that a trial invoked Lean before its deadline. Use --help for all explicit path flags; there are no private-machine default paths. A clean full source-only replay of the strongest accepted .96699/n369 theorem is supplied separately by `estimates/early369/reproduce.py`, which requires no preexisting application bank.

The focused outcomes include real failures: V1r0 CubeSecondary.lean fails elaboration at line182; its earlier version and general transport also fail. Those source files are preserved unchanged. A failed proof is not evidence the mathematical statement is false. V0r0 and V0r1 completed analytic headline proofs, while V1r1 has completed endpoint/profile lemmas but its strongest trapezoid ANT results remain written/external E. See CUBE_INDEPENDENT_REVIEW.json for exact scope and source assumptions.

`evidence/cube-replays/` preserves concise exact original receipts, source plans, audit/type/axiom output and failure diagnostics. No object banks, caches, private model reasoning or large regenerable numerical datasets are included. Original sources, source manifests, program parameters, dependency identities, complete commands and cryptographic hashes are retained in those files and their referenced pinned baseline/support records. Historical absolute paths in receipts record where a run actually occurred; the portable launchers accept caller-chosen directories.

The portable numerical helper was actually executed on the complete V1r1 scalar/sinc/finite-cover pipeline in normal, O and OO child modes; all three numerical stdout sets equal the original historical replays byte for byte. `test_replay_cli.py` additionally exercises 18 real rejection cases with the controller itself running under normal, -O and -OO. New portable receipts are separately named and never replace historical receipts.
