재현·검사·후속 작업

함께 제공하는 소스·증거 묶음은 두 최종 결과, 정확한 수학·문헌 원장, 중립 RH 통합, 완성된 증명 소스, 수치 알고리즘·매개변수, 컴파일러·의존성 커밋, 재현 명령, 원 실패 기록, 해시를 보존한다. 새 증명 재실행과 새 발견 실험은 별도 명령이다. 증명 재실행은 결정적이며 모델이 필요 없다. 발견을 반복하려면 같은 도구·격리 서비스와 사용 가능한 모델 접근이 필요하며 확률적인 출력이 같을 수는 없다. 문헌 입력인 출판 계산은 영구 참고 위치를 유지하고 래퍼가 몰래 다시 생성한 것으로 취급하지 않는다.

Python 빌드·채택 검사기 MertensPositive/replay.py를 일반, -O, -OO 모드에서 각각 실행했으며 매 실행마다 Lean 모듈을 다시 검사했다. Python 최적화에서도 채택 조건이 실제 작동하는지 시험한 것이며 서로 다른 Lean 증명 모드가 아니다. assert를 사용하는 원 탐색 스크립트는 별도로 보존했고 검토자 검사는 명시적인 오류 조건을 사용한다.

파일 용도 README.md 새 환경 준비·명령·한계 RESULTS.json 정확한 명제·범위·가정·공백 MertensPositive/FINAL_THEOREM_TYPE.txt 컴파일러가 출력한 실제 정리 매개변수 MERTENS_POSITIVE_PROOF.html 완전한 서면 증명과 문헌 명제 Ramanujan640/src/FinalResult.lean 실수 전체 6,400억 증명의 실제 소비 정리 review/final-NL/REVIEW.html 독립 NL 유효성·전체 함수 비교 review/final-IEANTN/REVIEW.html 독립 IEANTN 유효성·출처 검토 HISTORICAL_QRH_FUNCTIONS.json 후속 전체 곡선 식과 원래39개 식별자

이제 후속 수학 작업은 구체적이다. 더 강한 6,100억 경로와 NL 해석 경로를 형식화하고, 실제 li 정의의 두 연결을 증명하며, 마지막 실패점 정리의 완전한 소스 우선 증명이 필요하다면 남은 유한 방향성 개수 제공자를 구현하는 것이다. IEANTN의 모든 빈 증명을 무작정 채우는 일이 아니다. 완료한 재실행 결과는 보존하며, 바이트 검증 후 목록으로 특정한 실험 소유의 재생성 가능한 중복만 삭제할 수 있다. 원 소스, 확정 입력, 채택한 증명은 유지한다.
