# Pinned generic prerequisites for the isolated RH proof replay

These helpers repair missing **generic Mathlib build artifacts**, without changing mathematical sources, accepted application objects, or the historical failed run. They do not establish a new mathematical result or source-first PV.

The original clean replay stopped at module 81, `OcticQuadrature`, after preserving 80 successful modules. Its error referred to the pinned `Walk.Subwalks` object. A complete traversal of the actual selected source headers subsequently found four other missing graph modules. The helpers compiled those four from the same pinned Mathlib source and reproduced the failed application trigger in scratch. The first symlink overlay was intentionally preserved but was incompatible with the strict generic-context validator. The accepted additive context uses a real-file Mathlib snapshot, with its library path registered consistently in both context inventories.

Run from the network repository root, using fresh absolute output directories:

```sh
python3 Solutions/RHOcticPush.v1/ramanujan/generic-prereq/preflight.py \
  --context /absolute/original/GENERIC_CONTEXT.json \
  --out /absolute/fresh/preflight.json
python3 Solutions/RHOcticPush.v1/ramanujan/generic-prereq/complete.py \
  --preflight /absolute/fresh/preflight.json \
  --failed-application /absolute/preserved/failed-primary \
  --out /absolute/fresh/generic-completion
python3 Solutions/RHOcticPush.v1/ramanujan/generic-prereq/materialize.py \
  --completed /absolute/fresh/generic-completion \
  --out /absolute/fresh/materialized-context
```

`preflight.py` defaults to the explicit 693-module source universe. To include the later 19-module spectral append, use:

```sh
python3 Solutions/RHOcticPush.v1/ramanujan/generic-prereq/preflight.py \
  --context /absolute/fresh/materialized-context/GENERIC_CONTEXT.json \
  --append-source-manifest Solutions/RHOcticPush.v1/integration/spectral_final/capture/SOURCE_CLOSURE.json \
  --expected-application-modules 712 \
  --out /absolute/fresh/preflight-712.json
```

Source headers define the generic dependency inventory; sparse historical `generic_imports` metadata is reported separately. The parser handles comments, the Lean `module` header, and the `import all` keyword. A source inventory is followed by actual Lean import/build probes, rather than being treated as successful compilation.

The recorded run checked all 712 application source hashes and traversed 8,799 pinned generic modules. The owned materialized Mathlib snapshot contains 110,386 regular files totaling 6,143,965,775 bytes. Both full `import Mathlib` and the exact failed `OcticQuadrature` source compiled successfully. The strict clean-recovery controller accepted the new context. Its subsequent full mathematical replay is a separate experiment; the prerequisite helper does not promote the old failed run to success.

`SOURCE_FREEZE.json` records source hashes, the observed receipts, and context pins. The compiler is Lean 4.34.0-rc2; Mathlib is commit `71a80585ee495fc24472fd0eaffc89d94e4fd8d6`. Generic compiler/runtime/library artifacts remain within the existing trusted environment. The helper uses up to 64 GiB address space for each sequential build, admits work only with at least 512 GiB host reserve plus that allowance, and checks disk independently. Preserve the materialized context while any replay uses it. After a replay has finished, the generic snapshot can be regenerated by these commands; never delete original caches or accepted application artifacts.
