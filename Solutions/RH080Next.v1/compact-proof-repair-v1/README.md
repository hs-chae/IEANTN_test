# Portable compact FFT proof repair

This is an additive source-only proof assembly for the original W4 numerical
program. It changes two Lean proof bodies (`top_shape`, `numerator_checked`) and
adds two fixed, already kernel-checked helper modules. It preserves the numerical
C source, algorithm, input, all 937 N24 CSVs, all original generated numerical
sources, parameters, mathematical statements and analytic assumptions.

The mathematical candidate remains **UNTRUSTED_W4_DAG_PROPOSAL_NOT_PROOF_NOT_PV**.
Source preparation is not numerical proof acceptance and is not source-first
program verification. The original checker still generates its own exact original
29-root typed ClaimAudit; a candidate cannot supply or replace that audit.

## Publication boundary

This additive v2 mirror excludes nonessential debug notes and private process-argument
dumps. Actual mathematical source, OOM/stall records, compiler/gate/test receipts,
source/object hashes and portable runtime files remain unchanged. Original private
history and the prior review candidate are retained outside this public package.

## Files and scope

* `helpers/`: the two actual accepted Lean helper sources, byte-identical to the
  historical run.
* `tools/generate_compact_final_v2.py`: the actual accepted portable generator.
* `tools/derive_compact_candidate.py`: validates the original locked inventory,
  preserves its original PLAN, derives only the permitted proof sources, and
  leaves the candidate untrusted. The import-only diagnostic is excluded.
* `tools/compact_contract.py` and `locked/`: exact original numeric hashes,
  mathematical fields, twelve unchanged mathematical execution/data foundations,
  input, approved Final/helper hashes and original Audit templates.
* `tools/verify_fresh_compact.py`: adds that preservation contract to the unchanged
  original fresh-checker gate. Acceptance requires every fresh source/receipt/object,
  the original typed consumers, Std3 only and actual production resource evidence.
* `tools/export_fresh_compact.py`: creates an immutable source-associated provider
  bank from an independently accepted fresh run; it performs no compilation.
* `historical-executed/`, `evidence/`, and
  `ACTUAL_TO_PUBLICATION_SOURCE_MAPPING.json`: actual executed historical code and
  receipts with original/publication SHA256 mappings. Historical absolute paths
  document those runs and are not portable clean entrypoints.
* `RUNTIME_SOURCE_CLOSURE.json`: package files and required existing repository
  source/data dependencies for the final clean source bundle.

N24 has 1020 original proposed modules. The derived proposal has 1022 modules;
with the twelve original foundations and checker-owned audit, the cold checker
must compile **1035 mathematical modules**. S13 analogously has 109 proposed
modules and 122 complete mathematical modules. No diagnostic probe is included.

## Clean source preparation

Use the original pinned repository and dependencies. This package belongs under
`Solutions/RH080Next.v1/compact-proof-repair-v1`. The commands use paths chosen by
the caller; they require no historical `/data/ivy-...` checkout or proof objects.
The original mathematical input must exist at its existing repository location.
Its exact bytes are also preserved in `locked/w4-input.json` for comparison.

```sh
TASK_PROJECT="$REPO/Solutions/RH080Next.v1"
TASK_PACKAGE="$TASK_PROJECT/compact-proof-repair-v1"
python3 "$TASK_PACKAGE/tools/prepare_clean_compact_candidate.py" \
  --stage 24 --project-root "$TASK_PROJECT" --work "$TASK_WORK/source"
```

This executes the unchanged original producer first. It records the original
1020-module/937-payload expectations separately before deriving
`$TASK_WORK/source/compact-candidate`. That derived directory preserves
`ORIGINAL_PRODUCER_PLAN.json` byte-for-byte and an original Final snapshot. Only
Final's two proof bodies and two helper files differ. Original numeric files and
CSVs are hardlinked, never overwritten. `--storage copy` is available on the
lower-level derivation command when caller-owned destinations are on another
filesystem; the storage allowance must still be respected.

For an original candidate already regenerated by the existing driver:

```sh
python3 "$TASK_PACKAGE/tools/derive_compact_candidate.py" \
  --candidate "$TASK_WORK/original-candidate" \
  --out "$TASK_WORK/compact-candidate" --project-root "$TASK_PROJECT" \
  --input "$TASK_PACKAGE/locked/w4-input.json"
```

All original numerical source/data hashes and all mathematical fields are checked
against the locked original inventory. A self-consistent altered candidate PLAN
cannot redefine the accepted numeric expectations. All 31 N24 public declaration
headers remain identical; only the two permitted bodies change.

## Actual cold numerical verification

Run the unchanged original checker through its existing unlimited-virtual-AS
wrapper. For N24, launch the **whole generation/checking pipeline** inside an owned
300 GiB/no-swap cgroup, with the existing unchanged
`pv/supervise_resource_run.py` and process-only THP policy wrapper. Admission
requires genuinely available RAM at least 1 TiB and independently free disk at
least 1 TiB. Preserve the host's 256 GiB reserve, original scratch guards and
separate source/command/resource receipts. Do not equate unlimited virtual AS
with unlimited RAM. Do not run N24 outside the approved resource supervision.

The exact numerical checker child command is:

```sh
python3 -u "$TASK_PROJECT/dual/reproduce_fft_dag_physical_v2.py" \
  --context "$TASK_CONTEXT" --candidate "$TASK_WORK/source/compact-candidate" \
  --run "$TASK_WORK/cold-kernel" --workers 12 --worker-virtual-as unlimited
```

This wrapper executes the unchanged original `reproduce_fft_dag_v2.py`. It
imports no prior application objects. That checker inventories both helpers,
compiles all 1035 modules and generates the original typed ClaimAudit itself.

After the actual checker and owned supervisor finish, run each of normal, `-O`
and `-OO` with fresh receipt paths:

```sh
python3 "$TASK_PACKAGE/tools/verify_fresh_compact.py" \
  --project-root "$TASK_PROJECT" --run "$TASK_WORK/cold-kernel" \
  --context "$TASK_CONTEXT" --candidate "$TASK_WORK/source/compact-candidate" \
  --output "$TASK_WORK/accepted-normal.json" \
  --supervisor "$TASK_SUPERVISOR_RECEIPT" --command-plan "$TASK_COMMAND_PLAN" \
  --stdout "$TASK_SUPERVISOR_STDOUT" --stderr "$TASK_SUPERVISOR_STDERR" \
  --unit "$TASK_OWNED_UNIT"
```

Then export the complete accepted provider bank:

```sh
python3 "$TASK_PACKAGE/tools/export_fresh_compact.py" \
  --project-root "$TASK_PROJECT" --base "$TASK_WORK/cold-kernel" \
  --context "$TASK_CONTEXT" --candidate "$TASK_WORK/source/compact-candidate" \
  --accepted "$TASK_WORK/accepted-normal.json" --run "$TASK_WORK/format-bank"
```

The export has the existing linked-helper `PLAN.source_rows` format and normalized
`exitcode = 0` compiler receipts. It preserves original source/receipt/object
association and uses immutable hardlinks for large artifacts. C/ANT consumers
must still actually compile before claiming combined source-first PV.

## Bounded tests and current evidence

`tools/test_portable_contract.py` performs actual normal/-O/-OO clean-source and
negative mutation controls. Six positive CLIs and 33 rejected cases completed in
the publication study, including N24's full original 937-payload hash preservation.
The three positive S13 cases regenerate original numerical data independently;
source-only proposals and forged acceptance receipts cannot be promoted.

`tools/run_small_clean_smoke.py` is the optional actual **S13-only** cold proof,
three-mode gate and export smoke. It requires an owned 64 GiB/no-swap resource
unit and a sufficient host reserve, and is not an N24/681 replay. It actually completed the full122-module cold build, all18 original typed
Std3 consumers, normal/-O/-OO fresh gates and immutable export in499.522 seconds;
Final took169.313 seconds with GNU maximum RSS34,301,428 KiB and actual OOM0.
See `evidence/portable-s13-cold-smoke-RESULT.json`.

The historical accepted N24 result used 1031 source-cold-lineage numerical modules
plus four newly compiled mathematical proof modules. Its exact original 29 typed
claims passed all three full independent gates and actual supervisor OOM0. Final
compiled in 163.464 seconds, with GNU maximum RSS 37,407,168 KiB. That historical
result is distinct from a new monolithic clean replay of this package. No new
heavy fresh N24 or 681-module replay is claimed by this publication package.

## Trust and cleanup

These numerical proofs use the Lean kernel and the recorded standard axioms only;
no new axioms, sorry or native execution facts are introduced. Generic pinned
compiler/runtime, Python, OS/API and hardware infrastructure retain the existing
trust boundary. This package does not by itself establish C source-to-execution
correspondence or complete the C-to-ANT path.

Keep original research sources, original locked inputs, accepted proof artifacts,
source/code receipts and hashes. Generated temporary data may be removed only
from verified experiment-owned directories after deterministic regeneration and
reproduction have actually been checked. No original candidate or historical
outcome is overwritten by this package.
