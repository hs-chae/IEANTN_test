# Check and expose an accepted W4 FFT proof bank

These commands keep the numerical certificate checker, candidate, original
coefficient file, 16,777,216-point grid, rounding and target numerator
7,813,568,381,279,800 unchanged. A certificate proof is kernel-only verification.
The separately proved C source execution and actual ANT consumer are required
before calling the complete chain source-first PV.

## Continue the historical source-cold lineage

`resume_fft_dag_source_cold_v2.py` validates the 992 successful original compiler
receipts and four successful receipts from the first continuation, then compiles
the 37 remaining modules. The first continuation was interrupted by a supervisor
disk-scan exception; its final OOM counters are unavailable. The original scratch
stop and this interruption remain recorded. Neither is rewritten as success.

The nested controller, helper and original checker are immutable. Each of the
1,033 final source/object/compiler receipts retains its actual compilation
directory and phase. Candidate literal inputs and accepted objects are hardlinked
to the fresh destination. No unrelated application object cache is used.

After the actual mathematical run and owned supervisor finish, run:

```sh
python3 Solutions/RH080Next.v1/dual/verify_fft_dag_nested_resume.py \
  --context /path/to/pinned-context.json --candidate /path/to/fixed-candidate \
  --run /path/to/completed-nested-run --output /fresh/accepted.json \
  --supervisor /path/to/actual-supervisor.json \
  --command-plan /path/to/actual-command.json \
  --stdout /path/to/actual-supervisor.stdout \
  --stderr /path/to/actual-supervisor.stderr --unit actual-owned.service
```

The independent gate checks every original/fresh source, candidate CSV, object,
command, timing/log hash, completed exit status, diagnostic and dependency route.
It rechecks the unchanged independently specified typed consumer and all 29
standard-axiom roots. It also checks the actual 992/4/37 phase counts and owned
300 GiB/no-swap memory evidence. Actual final OOM counter deltas must be zero;
absence of a completed resource receipt cannot establish this.

`watch_fft_dag_nested_completion.py` is an optional observer that waits for the
actual completed supervisor, executes this gate in normal, `-O` and `-OO` modes,
and performs the format export only after all three pass. It never controls or
terminates the mathematical worker. Its own failure creates no acceptance.

## Reproduce from a new clean run

A clean reproduction does not need the historical interrupted directories.
Generate the fixed candidate with `produce_fft_dag_certificate.py` using the
original stage, chunk and input parameters, then use the unchanged
`reproduce_fft_dag_v2.py`. Rebuild every application module from pinned generic
dependencies in a fresh destination.

Use `verify_fft_dag_fresh.py` with the same arguments as the nested gate. Its
resource receipt must record the actual direct original-v2 command, under the
public `pv/supervise_resource_run.py` supervisor. It checks every fresh module and
the same typed claim without assuming any historical continuation. The
`--proof-only-toy` option is strictly limited to the 13-stage test fixture and
cannot accept a production 24-stage result.

## Format-only export for downstream Lean consumers

For an independently accepted nested run:

```sh
python3 Solutions/RH080Next.v1/dual/export_fft_dag_bank.py \
  --context /path/to/pinned-context.json --candidate /path/to/fixed-candidate \
  --base /path/to/completed-nested-run --accepted /path/to/accepted.json \
  --run /fresh/associated-bank
```

For an independently accepted new clean run, use
`export_fft_dag_fresh_bank.py` with the same options. This wrapper also requires
the exact current fresh-gate identity and reruns its mathematical evidence check.

The adapter hardlinks all source, literal, object and log files. It writes only
new format metadata: `PLAN.source_rows` records module/origin/snapshot/source
hash/imports, and each normalized `COMPILED` record supplies `exitcode=0` while
retaining the original compiler receipt, log directory, logical command root and
compilation phase. This is neither new compilation nor new numerical evidence.
The original successful receipts remain immutable.

## Checked controls

Actual 13-stage fixtures exercise the same public CLIs under normal, `-O` and
`-OO`. Nested controls include 21 prefix/continuation tamper rejections and 18
completion-gate rejections. Format controls check hardlink identities and reject
incorrect acceptance receipts. A real downstream hardlink compiler consumed an
exported bank and successfully compiled its source dependency. New-clean controls
provide three positive gates, 15 rejection cases and three actual format exports.
These bounded controls do not themselves establish production completion.

The compiler, documented generic C runtime/ABI/OS/hardware contracts and physical
execution association remain separate trust boundaries. No observed stdout,
successful application initialization or correct numerical answer is introduced
as an unverified Lean premise by these receipt adapters.
