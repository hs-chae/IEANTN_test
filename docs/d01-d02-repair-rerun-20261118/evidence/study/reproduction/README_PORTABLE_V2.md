# Reproduce the finalized numerical portfolios from a relocated source tree

This is an additive, **no-model numerical reproduction** package. It copies the original mathematical programs, parameters, paper inputs, task packets, output evidence and Root admission records without changing their bytes. It does not establish a complete analytic Lean proof, source-first program verification, optimality or an overall exposure advantage. New numerical outputs never become verified IEANTN premises merely by matching this package.

The first collection covers the twelve finalized portfolios C001–C009, C013, C014 and C019. The other twelve canonical cases remain explicitly listed as not yet finalized. Future collection snapshots can add their exact completed recipes; they cannot replace a fixed candidate or its original outcome. A collection is preparation, not evidence that every clean reproduction ran. Original-host successful clean runs have their separate final resource/output receipts preserved in the source tree; relocation itself requires a new run.

## What is preserved

`portable/EXACT_SOURCE_MANIFEST.json` lists every original file with its original absolute path, portable relative path, SHA-256 and size. The original and portable hashes must agree. `portable/RELOCATION_CONFIG.json` binds that manifest, the exact executor components and the current case collection. Original JSON, mathematical prose, C/C++/Python programs and their embedded absolute metadata remain byte-identical. The adapter resolves only recorded original-workspace path references through the explicit original/new root map. It does not rewrite mathematical sources, old claims, expected outputs or hashes.

Each case plan retains the entire candidate and review LOCK populations, seven original PDF/text pairs, exact old execution identities, all essential numerical modes and their output contracts. C019 explicitly preserves its42 primary export files separately from its74-file review-only own-history view. Past review verdicts are provenance, not mathematical premises. Historical false trials, withdrawn assertions and later source corrections remain history rather than being silently promoted to a valid bound.

## Clean Linux prerequisites

The original worker contract is x86-64 Linux, CPython3.10.12 at `/usr/bin/python3.10`, GNU GCC/G++11.4.0 (Ubuntu11.4.0-1ubuntu1~22.04.3), their standard headers/libraries and libubsan for the listed sanitizer jobs. Generic mpmath1.3.0 and sympy1.12 source trees are bundled with their complete file manifests. The source tree includes the exact existing namespace helper and template. No Codex installation, authentication file, account, model server, network download or Lean installation is used by the reproduction adapter.

The trusted outer controller is ordinary Python3.10 or newer with its standard library. It is different from the isolated numerical interpreter. The host needs systemd user services, a user manager and cgroup-v2 memory/CPU accounting, and the same existing private mount/network namespace support. The unchanged namespace template explicitly binds the host's generic Python/tools/library paths; inspect its recorded entries before running. A different distribution, compiler or mathematical runtime must not be described as the historical identical toolchain. The actual new interpreter/compiler/binary/kernel identities are recorded by the run.

The unchanged capacity policy needs eight CPUs from the fixed slots32–79 and at least one available slot. Therefore the host affinity must actually include an appropriate eight-CPU slot; a small laptop is not an equivalent production host. Each job reserves64GiB RAM, eight CPUs and25GiB scratch, with zero swap. Its actual private writable namespace has24GiB work and1GiB temporary storage; outputs are exported through the existing bounded64MiB pipe. The shared policy allows at most six such jobs and retains a512GiB host-memory reserve. Admission independently checks available RAM against that reserve plus existing reservations plus the new64GiB, and free disk against1TiB plus the300GiB global scratch allowance. Disk availability is never counted as RAM. No obsolete4GiB limit or arbitrary numerical wall deadline is introduced.

On the original live host, use its existing shared registry; the adapter rejects a separate registry that would evade concurrent reservations. On a clean host, provide one explicit shared registry outside the source tree and bind it in the new execution authority. Every concurrently running study participant must use that registry. Namespace setup, host configuration or missing prerequisites are not changed automatically by this package.

## Validate the extracted files without executing mathematics

Extract the archive to a fresh private directory. Set `TREE` to the extracted `source-tree` directory. Shell variables in these examples are task-specific; they do not change HOME or CODEX_HOME.

```sh
TREE=/absolute/path/to/source-tree
STUDY="$TREE/ieantn-d01-d02-repair-rerun-20261118"
python3 -I -B "$STUDY/scripts/portable_relocation_metadata_v2.py" \
  --source-root "$TREE" --config "$TREE/portable/RELOCATION_CONFIG.json" --check
```

Success reports the exact file census, ready cases and pending cases. This command only reads and hashes files. To validate the complete command/source/mount plan for a case, find its `job_plan` in the collection named by the configuration. Convert that original absolute job path to the same relative path below `TREE` (the original workspace prefix is explicitly recorded in the configuration):

```sh
JOB="$STUDY/coordinator-private/newer-finalized-numerical-reproduction-preparation-v2/FOLLOWUP-C019.JOB_PLAN_UNSIGNED.json"
REGISTRY=/absolute/path/to/shared-host-resource-registry
python3 -I -B "$STUDY/scripts/run_portable_numerical_reproduction_relocated_v2.py" \
  --job "$JOB" --source-root "$TREE" \
  --relocation-config "$TREE/portable/RELOCATION_CONFIG.json" \
  --resource-registry-root "$REGISTRY" \
  --out "$STUDY/evidence/portable-relocated-reproduction-v2/FOLLOWUP-C019" \
  --resource-out "$STUDY/resources/portable-relocated-reproduction-v2/FOLLOWUP-C019" --check
```

The ready status explicitly says metadata only: no reservation, namespace, model, compiler or numerical child has run. Acceptance checks use explicit errors and strict duplicate/nonfinite JSON parsing. The accompanying control receipt distinguishes actual normal, `-O` and `-OO` metadata tests, deliberate negative fixtures and synthetic output-contract tests from numerical results. Original mathematical Python programs are kept unchanged and run with normal assertions enabled: every numerical Python argv uses normal `/usr/bin/python3.10`, and the outer wrapper removes PYTHONOPTIMIZE.

## Authorize and run one exact case

Before a real run, the trusted experiment coordinator reviews the exact new executor source/configuration, complete case plan, intended output paths, actual host environment and shared resource registry. The coordinator issues a new source-approval receipt, a reviewed copy of the case job, and an exact execution receipt binding their hashes and all new absolute output paths. The adapter accepts changes to authority metadata only; all scientific code, algorithms, literal parameters, numerical workloads and expected historical outputs must still equal the frozen collection plan. The Root role in these JSON receipts means the trusted experimental coordinator, not the operating-system root user. These are administrative trust records, not signatures proving mathematics.

Source approval is created after source assembly and is bound separately by the exact execution authority. It is deliberately not placed into the manifest it signs; this avoids a circular hash dependency. A copied original-host authority does not authorize a different extracted path or host registry. Metadata checks and a successful file copy never confer execution authority.

Use the same command above with the separately reviewed job and `--root-authorization /absolute/path/to/EXECUTION_ROOT.json`, replacing `--check` by `--run`. The existing registered executor owns admission, the isolated service, measurements, interruption handling, complete process/cgroup drain and reservation release. No shell-evaluated numerical command is constructed. The exact job's literal argument lists run every mandatory child; an inexpensive check cannot replace a larger sieve. Long finite scans have sufficient CPU opportunity and no obsolete fixed wall cutoff. On interruption, retain partial evidence; do not relabel it successful or automatically overwrite the attempt.

## Results, trust and cleanup

A successful numerical child list is not the final receipt. Only `FINAL_REPRODUCTION_RECEIPT.json` with status `PASS_EXACT_NUMERICAL_REPRODUCTION_AND_ACTUAL_DRAIN` records complete output verification **and** actual service/cgroup drain and reservation release. Keep the actual resource receipt, selected-output manifest, environment/compiled-binary receipt, original/new source/job hashes, full stdout/stderr or the explicitly disclosed C007 contract, wall/CPU time, peak memory/scratch and OOM evidence. A mathematical source correction does not disappear because its program reproduced the same numbers.

Original mathematical statements and analytic assumptions remain unchanged. Pinned published finite-RH/prime/density computations remain at their documented literature-backed tier unless a listed run actually regenerates them. Ordinary GCC/Python/runtime/OS/hardware execution remains trusted; output hashing and original assertions are not source-first PV. No complete new Lean proof, verified-network node or experimental arm ranking is claimed here.

The namespace's large arrays, generated executables, directed-log input files and restored work copies are deterministic temporary data. The fixed essential outputs are exported before actual drain. After a real successful run and its regeneration procedure have been checked, retain concise accepted receipts and essential original evidence, then preview and remove only the run's verified-regenerable temporary data. Do not remove original sources, locked inputs, irreplaceable certificates, accepted proof artifacts, another workspace, or the only reproducibility copy. No automatic broad cleanup command is supplied.
